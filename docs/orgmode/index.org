* eb-pipeline

eb-pipeline runs a site's EasyBuild build lists from one TOML file, the site file, which describes the site: its targets, the scheduler allocation of each phase, its paths, inode admission, modules, caches, log handling and licences.
From the site file, a build list and a target, it plans the commands of each phase and starts them as subprocesses: eb-stack to shard the list and admit each build, EasyBuild to fetch the sources and build, eb-keep-logs to keep a failed build's logs and rotate the log tree, and eb-staged-rebuild for a line that rebuilds a live install.
A CI system, a cron job or a person on a login node then passes a list and a target, and reads an exit code and a result file.
Nothing about a site lives in eb-pipeline: the site file holds it, and the environment can set any of its values for one deployment.
