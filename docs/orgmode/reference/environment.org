* Environment variables

The variables =eb-pipeline= reads in place of an option or a site file value, the ones a run reads because the site file names them, and the ones it sets for the commands it starts.

** Options

An option that is not on the command line takes its value from its variable.
An option on the command line wins.

| Variable                 | Option         | Commands                                     |
|--------------------------+----------------+----------------------------------------------|
| =EB_PIPELINE_SITE=       | =--site=       | =check=, =explain=, =targets=, =plan=, =run= |
| =EB_PIPELINE_LIST=       | =--list=       | =plan=, =run=                                |
| =EB_PIPELINE_TARGET=     | =--target=     | =explain=, =plan=, =run=                     |
| =EB_PIPELINE_BUILD_TYPE= | =--build-type= | =explain=, =plan=, =run=                     |
| =EB_PIPELINE_RUN_ID=     | =--run-id=     | =plan=, =run=                                |
| =EB_PIPELINE_LOG_STAMP=  | =--log-stamp=  | =plan=, =run=                                |
| =EB_PIPELINE_LISTS_DIR=  | =--lists-dir=  | =check=                                      |

=--out=, =--result=, =--shard-plan=, =--format=, =--dry-run= and =--probe-tools= have no variable.

** Site file values

=EB_PIPELINE__SECTION__KEY=VALUE= sets one value of the site file, after the file is read and before it is checked.
Every command that reads a site file applies these variables.

- The name after =EB_PIPELINE__= is split at each =__=, and each part, lowercased, names a table or, last, the key.
  =EB_PIPELINE__FILESYSTEMS__SCRATCH= sets =scratch= in =[filesystems]=, and =EB_PIPELINE__LOGS__ROTATE__DELETE_AFTER_DAYS= sets =delete_after_days= in =[logs.rotate]=.
- A part must hold letters, digits and underscores only, and none may be empty.
- =VALUE= is read as a TOML value, such as =true=, =16=, ="16"= or =["a", "b"]=, and as a string when it is not one.
  =/scratch/alice= is the string ="/scratch/alice"=.
- A table on the path that the file does not have is made.
- A path that reaches into an array of tables, such as =targets=, is refused: the values of a target stay in the file.
  So is a path that ends at a table, or that passes through a value that is not a table.
- The variables apply in the order of their names, whatever the order of the environment.
- Each one writes =INFO [site] -: KEY set from NAME= to stderr, with the key and never the value.

The result is checked like the file itself, so an unknown key or a value of the wrong type exits 2 with =invalid site file after environment overrides:= and the reason.
Since every part is lowercased, these variables cannot set a key that has an upper-case letter, such as a package name under =[modules.package_env]=.

** Read during a run

The site file names these variables; =run= reads them before the first build.
=plan= and =run --dry-run= show =${NAME}= in their place.

| Variable                                                           | Use                                                                                                                                                                                    |
|--------------------------------------------------------------------+----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| the one named by =admission.job_id_env=, =SLURM_JOB_ID= by default | The job id that =eb-stack stack admit= reserves for. With admission on, =run= refuses with exit 78 before any build when it is unset or not a positive integer without a leading zero. |
| the one named by =targets.route.receipt_digest_env=                | A digest that the routed commands get as =EB_PIPELINE_ROUTE_RECEIPT_DIGEST=. =run= refuses with exit 78 when it is unset or empty.                                                     |
| each one named in =shards.installed_modules_dirs_from_env=         | Module trees, separated by =:=, added to =shards.installed_modules_dirs=. =run= refuses with exit 78 when one is unset; an empty one adds nothing.                                     |

=eb-pipeline= does not read =EB_PIPELINE_SITE_NAME=; =EB_PIPELINE__SITE__NAME=, with two underscores, is the variable that sets =name= in the site file.

=[modules.eessi]= is on when the site file has the table and its =enabled= is not =false=.
=[licences]= is on when its =enabled= and =enforce= are not =false=.
=EESSI= stands for the European Environment for Scientific Software Installations.

*** The module wrapper

When =modules.init= is not empty, =modules.unuse_path= is =true= or =modules.shell_init= is set, the shard, prefetch, build, keep-failed and cache commands start through =modules.shell=, which reads three of the variables above:

1. =EB_PIPELINE_SHELL_INIT=: the file it sources first, when set.
2. =EB_PIPELINE_UNUSE_PATH=: when set, it empties =MODULEPATH=.
3. =EB_PIPELINE_MODULES=: it runs =module purge=, then =module load= for each name in it, in order, then the command.
   It splits the variable at white space and gives each name to =module load= as written: a name with a pattern in it, such as =GCC/*=, is not matched against file names.

The wrapper is a script for a POSIX shell: =check= accepts =sh=, =bash=, =dash=, =ash=, =ksh=, =ksh93=, =mksh= and =yash= as =modules.shell=, by name or by path, and refuses any other.
zsh would load the names of =EB_PIPELINE_MODULES= as one, since it does not split an unquoted variable, and csh, tcsh and fish cannot parse the script.
The admit and rotate commands start without it.
