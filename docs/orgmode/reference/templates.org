* The site file templates

=eb-pipeline init= writes a site file from one of three built-in templates.
Each is a complete site file that =check= finds valid, with placeholder values only: names in angle brackets, such as =<build-user>=, and paths and names, such as =/opt/eb= and =small-lab=, that stand for the site's own.
The examples on this page come from =docs/examples/templates.sh=.

#+begin_src bash
eb-pipeline init --list
#+end_src

#+begin_example
workstation      One machine, no scheduler: every phase runs on this host; no EESSI, quota or licences
small-cluster    Slurm, one CPU target; no EESSI, inode quota or licences
eessi-site       Slurm, CPU and GPU targets on an EESSI site layer, with quota, caches and licences
#+end_example

| Template        | Targets                            | Phases it turns on, besides =preflight= and =build=              |
|-----------------+------------------------------------+------------------------------------------------------------------|
| =workstation=   | =cpu=                              | none                                                             |
| =small-cluster= | =cpu=                              | =logs=                                                           |
| =eessi-site=    | =cpu-a=, =cpu-b=, =gpu-a=, =gpu-b= | =licences=, =shard=, =sources=, =admission=, =caches= and =logs= |

=init --template NAME= prints the template, and =init --template NAME --out FILE= writes it to =FILE=.
With =--hints=, or with =EB_PIPELINE_INIT_HINTS=1=, =init= also prints next steps on stderr after it writes a file, including the =targets= command for templates with several targets.

#+begin_src bash
eb-pipeline init --template small-cluster --out small-cluster.toml
eb-pipeline check --site small-cluster.toml
#+end_src

#+begin_example
INFO [init] -: wrote template small-cluster to small-cluster.toml
INFO [check] small-lab: site file is valid
#+end_example

=init= refuses a file that exists, and exits 2, as it does for an unknown template or none:

#+begin_src bash
eb-pipeline init --template small-cluster --out small-cluster.toml
#+end_src

#+begin_example
ERROR [main] -: cannot create small-cluster.toml: File exists (os error 17)
#+end_example

** =workstation=

One machine with no scheduler, such as a workstation, a lab server or a continuous integration runner.
=kind = "local"= starts every command of a run on this host as a plain process, so no command goes through =srun=.
No module is loaded before a build: =eb= comes from =PATH=, for example from =pip install easybuild=.
EasyBuild still needs a module tool to write and find modules: source EESSI's init, which provides Lmod, or install Lmod, and set =EASYBUILD_MODULES_TOOL=Lmod=. =eb-pipeline check --site site.toml --probe-tools= says when this host has neither =eb= nor the module tool.
Each line runs as its own =eb= command with the line's options only, so a line whose dependencies are not installed yet needs =--robot= on the line.

#+INCLUDE: "../../../templates/workstation.toml" src toml

** =small-cluster=

A Slurm cluster with one CPU node type, and none of the European Environment for Scientific Software Installations (EESSI), an inode quota or licences.
Each command of a run starts with =srun= and the launch arguments of its role, from =[phase_defaults]=, and the build of a line runs with the =EasyBuild= module loaded.
A failed line keeps its EasyBuild log, and a run rotates the log tree with =eb-keep-logs rotate --compress-after 60=.

#+INCLUDE: "../../../templates/small-cluster.toml" src toml

** =eessi-site=

A site that installs into its own layer on top of EESSI, with two CPU and two GPU node types.
Its targets install where EESSI-extend puts a site installation for their =cpu_target= and =accel_target=.
The GPU target =gpu-a= keeps only the lines of a list that are for it, and wraps the commands of its CPU-only prerequisites in a route command, which build them with the hardware variables of another class.
A run admits each unit against an inode quota, shards the list, prefetches sources without the robot, writes module caches for =cpu-a= and =gpu-a=, rebuilds installed modules through eb-staged-rebuild with a state root per target, and checks that each licensed package has a group, a version threshold or an exemption.

#+begin_src bash
eb-pipeline init --template eessi-site --out eessi-site.toml
eb-pipeline check --site eessi-site.toml
eb-pipeline targets --site eessi-site.toml
#+end_src

#+begin_example
INFO [init] -: wrote template eessi-site to eessi-site.toml
INFO [check] cluster-a: site file is valid
cpu-a
cpu-b
gpu-a
gpu-b
#+end_example
