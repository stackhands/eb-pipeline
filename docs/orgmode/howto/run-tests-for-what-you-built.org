* Run the tests that cover what you built

A build list mixes applications and toolchains.
The tests worth running are the ones that cover the applications.
=eb-test-map= reads a map of software name to test name and the build list, and prints those tests.
An application with no row is a refusal: =has no test=.

The EESSI build-and-deploy bot does this with =tests/eessi_test_mapping/software_to_tests.yml= and then runs the [[https://eessi.io/docs/test-suite/][EESSI test suite]], which is ReFrame.
=eb-test-map= is that map for a site overlay. It does not run ReFrame itself.

* Before you start

- A build list of easyconfig file names, one per line, the list =eb-pipeline run --list= uses.
- A map of the applications that list installs, when you want test names. A toolchain does not need a row. =--format eessi-modules= does not use the map.

* Steps

1. Write the map. The first word is the software name, the part of the easyconfig's file name before the version. The second is the test name ReFrame, or the site's own suite, knows:

   #+begin_src text
   # software    test
   GROMACS       gromacs
   GROMACS       gromacs-perf
   FFTW          fftw
   #+end_src

   =GCC=, =GCCcore=, =foss=, =gfbf=, =gomkl=, =gompi=, =iimpi=, =intel= and =intel-compilers= are toolchains and are skipped.
   =--toolchain NAME= skips another.

2. Ask for the tests of one list:

   #+begin_src bash
   eb-test-map --map /opt/site/tests.tsv --list /opt/site/build.list
   #+end_src

   #+begin_example
   fftw
   gromacs
   gromacs-perf
   #+end_example

   =Python has no test in /opt/site/tests.tsv= on stderr, and exit 2, means an application in the list has no row.
   Nothing is printed in that case, so a later step does not run a subset and look finished.
   =--allow-unmapped= prints the tests that do exist, names the gap, and exits 0.
   =--format reframe= prints selectors a ReFrame run can pass as repeated =-n= arguments.

   #+begin_example
   -n ^fftw$
   -n ^gromacs$
   -n ^gromacs-perf$
   #+end_example

   To map only what built successfully in one run, use the run's result file:

   #+begin_src bash
   eb-test-map --map /opt/site/tests.tsv --result result-cpu.json
   #+end_src

   A resumed run records a prior successful line as =skipped= when its outputs still exist.
   Include those lines when selecting post-run tests:

   #+begin_src bash
   eb-test-map --map /opt/site/tests.tsv --result result-cpu.json --include-resumed
   #+end_src

   Ordinary skipped lines and failed lines stay excluded.

3. Make a clean build run that command before it refreshes module caches. =[checks].command= is split on spaces and is not a shell, so the paths are written out:

   #+begin_src toml
   [checks]
   command = "eb-test-map --map /opt/site/tests.tsv --list /opt/site/build.list"
   #+end_src

   Exit 2 fails the run, and the caches phase does not run.
   To run ReFrame on the names, the command is a script that calls =eb-test-map= and then ReFrame. The script's exit status is the check.

4. To give the European Environment for Scientific Software Installations (EESSI) test suite the modules that were built, without keeping a software-to-test map, ask for the module names:

   #+begin_src bash
   eb-test-map --format eessi-modules --list /opt/site/build.list
   #+end_src

   #+begin_example
   --setvar modules=FFTW/3.3.10-GCC-13.2.0,GROMACS/2024.1-foss-2023b
   #+end_example

   =GROMACS-2024.1-foss-2023b.eb= becomes =GROMACS/2024.1-foss-2023b=, and =zlib-1.3.1.eb= becomes =zlib/1.3.1=.
   The same version split as the map is used: the software name stops at the first component that starts with a digit, and the rest is the version, toolchain, and suffix.
   Toolchains are left out, including a name given with =--toolchain=.
   The names are sorted, and a repeated name is printed once.
   A script passes that line to ReFrame:

   #+begin_src bash
   reframe $(eb-test-map --format eessi-modules --list /opt/site/build.list)
   #+end_src

   ReFrame splits the value of =--setvar= on commas and does not drop spaces.
   =set_modules= in the test suite keeps a test only when every module name that test asks for is in the list.
   When the list has no application, the command prints nothing and exits 0, so the script does not pass an empty =modules= value.
   =--map= is not read. =--allow-unmapped= applies to =--format text= and =--format reframe= only.
   =[checks].command= is still not a shell, so this =reframe= line belongs in the same kind of script as step 3.

* If it fails

| Message | Cause | What to do |
|---------+-------+------------|
| =--map is required= or =--list or --result is required= | The default or =reframe= format was not given both =--map= and an input (=--list= or =--result=), or =--format eessi-modules= was not given an input. | Pass =--map= and =--list= (or =--result=) for test names. Pass =--list= (or =--result=) for module names. |
| =cannot read FILE= | The map, list, or result file is not there. | Use the path the build uses. |
| =SOFTWARE has no test in FILE= | An application in the list has no row, and it is not a toolchain. This applies to =--format text= and =--format reframe=. | Add a row, or pass =--toolchain NAME= when that software is a toolchain of the site's. The run stays failed until the map covers it. |
| =`FILE` is not an easyconfig= or =list line N: `FILE` is not an easyconfig= | A line is not an =.eb= file name. | Leave comments as lines that start with =#=. |
| =list line N: `FILE` has no version= | The file name has no component that starts with a digit, so it is not =Name/Version=. | Use =Name-Version.eb= or =Name-Version-Toolchain.eb=. |
| =list line N: `FILE` has a comma or a space in its module name= | That name would not stay one entry when ReFrame splits the list on commas. | Use a module name without a comma or a space. |
| =unknown --format `VALUE`; expected `text`, `reframe`, or `eessi-modules`= | The format is not =text=, =reframe=, or =eessi-modules=. | Omit =--format= for test names, or pass =reframe= or =eessi-modules=. |
