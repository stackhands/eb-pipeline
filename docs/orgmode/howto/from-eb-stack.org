* Build what eb-stack plans

Give a run the easystack or the build list that eb-stack writes, as eb-stack wrote it, instead of copying its entries into a build list by hand.
eb-stack decides what to build, and the run builds it.

** Before you start

- A site file that builds, such as the one of the [[file:../tutorials/first-build-list.org][tutorial]].
- A file that one of the eb-stack commands of step 1 wrote.

The output on this page comes from =docs/examples/from-eb-stack.sh=.
It gives two files that eb-stack 0.7.4 wrote, kept in =tests/fixtures/eb-stack/=, to the site file and the stand-in =eb= of the [[file:../tutorials/first-build-list.org][tutorial]].

** Steps

1. Pick the file to build from:

   | eb-stack command                            | What it writes                                                                              | Order              |
   |---------------------------------------------+---------------------------------------------------------------------------------------------+--------------------|
   | =stack solve --build-list-out FILE=         | A build list of easyconfig paths                                                            | Dependencies first |
   | =stack solve --jenkins-build-list-out FILE= | A build list of easyconfig file names, with their =eb= options                              | Dependencies first |
   | =stack order --out FILE=                    | A build list of easyconfig paths                                                            | Dependencies first |
   | =stack order --easystack-out FILE=          | An easystack                                                                                | Dependencies first |
   | =stack easystack --out FILE=                | An easystack, with the options of its =--option= arguments                                  | By file name       |
   | =rebuild-set=                               | An easystack for each EasyBuild version, under =rebuilds/=, each entry with =rebuild: true= | By file name       |

   A run builds the lines in the order of the file, one =eb= command for each, as =eb --easystack= builds the entries of an easystack.
   When the easyconfigs of a file sorted by name depend on each other, build from a file with the dependencies first.
2. Give the file to the run as =--list=, as eb-stack wrote it.
   A file whose name ends in =.yml= or =.yaml= is an easystack, and any other file is a build list.
   =rebuild-set= wrote this easystack for a patch to pigz:

   #+begin_src bash
   cat rebuild-set/rebuilds/20261117-eb-unknown-cve-patches.yml
   #+end_src

   #+begin_example
   # In-place patches, same filename and version.
   # Class must-rebuild only: the patched easyconfig, a bundle that ships it as an extension,
   # and, when --check-static was used, a dependent that defines an export of the patched library.
   # Generated by `eb-stack rebuild-set`.
   easyconfigs:
     - pigz-2.8-GCCcore-15.2.0.eb:
         options:
           rebuild: true
   #+end_example

3. Check what the run builds of it:

   #+begin_src bash
   eb-pipeline run --site site.toml --list rebuild-set/rebuilds/20261117-eb-unknown-cve-patches.yml --target cpu --build-type production --dry-run | grep "^\[build\]"
   #+end_src

   #+begin_example
   INFO [run] cpu: dry run: nothing executed
   [build] eb pigz-2.8-GCCcore-15.2.0.eb --rebuild
   #+end_example

   Each entry is one line: its easyconfig, with =.eb= added to a name without it, then its =options= as options of =eb=, sorted by name, as EasyBuild turns them into options:

   | In the easystack                            | On the line                                       |
   |---------------------------------------------+---------------------------------------------------|
   | =- pigz-2.8-GCCcore-15.2.0=                 | =pigz-2.8-GCCcore-15.2.0.eb=                      |
   | =rebuild: true=                             | =--rebuild=                                       |
   | =rebuild: yes=                              | =--rebuild=                                       |
   | =rebuild:=                                  | =--rebuild=                                       |
   | =robot: false=                              | =--disable-robot=                                 |
   | =f: true=                                   | =-f=                                              |
   | =parallel: 4=                               | =--parallel=4=                                    |
   | =cuda-compute-capabilities: '8.0'=          | =--cuda-compute-capabilities=8.0=                 |
   | =include-easyblocks: [a.py, b.py]=          | =--include-easyblocks=a.py,b.py=                  |
   | =amend: [versionsuffix=foo, toolchain=bar]= | =--amend=versionsuffix=foo --amend=toolchain=bar= |

   On a target that takes staged rebuilds, a =--rebuild= line whose module is installed goes through eb-staged-rebuild, as in [[file:staged-rebuilds.org][Rebuild installed software through eb-staged-rebuild]].
   eb-pipeline reads an easystack as YAML 1.2, and EasyBuild as YAML 1.1, so write values that the two read differently as both read them alike:
   - =yes=, =on=, =no= and =off= are booleans to both; eb-pipeline cannot tell a quoted value from a plain one, so a quoted =yes= is a boolean to it too.
   - A number with a point, such as =8.0=, goes in quotes, as eb-stack writes it; eb-pipeline refuses it without them, as Python and eb-pipeline write such a number differently.
   - A value with a leading zero, an underscore or a colon, such as =umask: '022'=, goes in quotes: EasyBuild reads a plain =022= as the number 18, and eb-pipeline as the text =022=.
4. A build list of eb-stack needs nothing more:

   #+begin_src bash
   cat stack.list
   eb-pipeline run --site site.toml --list stack.list --target cpu --build-type production --dry-run | grep "^\[build\]"
   #+end_src

   #+begin_example
   M4-1.4.20-GCCcore-15.2.0.eb
   Perl-5.42.0-GCCcore-15.2.0.eb
   Autoconf-2.72-GCCcore-15.2.0.eb
   pigz-2.8-GCCcore-15.2.0.eb
   INFO [run] cpu: dry run: nothing executed
   [build] eb M4-1.4.20-GCCcore-15.2.0.eb
   [build] eb Perl-5.42.0-GCCcore-15.2.0.eb
   [build] eb Autoconf-2.72-GCCcore-15.2.0.eb
   [build] eb pigz-2.8-GCCcore-15.2.0.eb
   #+end_example

** Check that it worked

A run builds each entry as a line:

#+begin_src bash
eb-pipeline run --site site.toml --list rebuild-set/rebuilds/20261117-eb-unknown-cve-patches.yml --target cpu --build-type production --log-stamp 20261117_090000; echo "exit $?"
#+end_src

#+begin_example
INFO [licences] cpu: not configured
INFO [shard] cpu: not configured
INFO [sources] cpu: not configured
INFO [admission] cpu: not configured
INFO [caches] cpu: not configured
INFO [logs] cpu: not configured
INFO [build] cpu: pigz-2.8-GCCcore-15.2.0: start
INFO [build] cpu: pigz-2.8-GCCcore-15.2.0: ok
exit 0
#+end_example

The output of each line names the command, which the stand-in =eb= prints:

#+begin_src bash
grep "^eb " $WORK/logs/20261117_090000/cpu/pigz-2.8-GCCcore-15.2.0.stdout.log
#+end_src

#+begin_example
eb pigz-2.8-GCCcore-15.2.0.eb --rebuild
#+end_example

With =[shards]=, the run writes the lines of an easystack to =easystack-TARGET.list= in its log directory, which =stack shard= reads as its build list; with =[targets.select]=, =selected-TARGET.list= holds them.

** If it fails

| Message                                                                                                                    | Cause                                                                               | What to do                                                           |
|----------------------------------------------------------------------------------------------------------------------------+-------------------------------------------------------------------------------------+----------------------------------------------------------------------|
| =ERROR [main] -: easystack typo.yml: entry 1: pigz-2.8-GCCcore-15.2.0.eb: only `options` can follow the name, not option=  | A key other than =options= under the name, here a typing error.                     | Write =options:=.                                                    |
| =ERROR [main] -: easystack FILE: entry N: the entry has 2 keys, NAME, options: indent `options` under the easyconfig name= | =options:= starts as far in as the name, which makes it a second key of the entry.  | Indent =options:= further than the name.                             |
| =ERROR [main] -: easystack FILE: entry N: NAME: the option `OPTION`: put `8.0` in quotes; ...=                             | A number with a point without quotes.                                               | Write it in quotes, such as ='8.0'=.                                 |
| =ERROR [main] -: easystack FILE: `easyconfigs` is not a list; start each entry with `- `=                                  | The entries under =easyconfigs:= do not start with a dash.                          | Start each entry with a dash.                                        |
| =ERROR [main] -: easystack FILE: there is no top-level `easyconfigs` key=                                                  | A build list whose name ends in =.yml= or =.yaml=, or an easystack of another form. | Name a build list otherwise; write the entries under =easyconfigs:=. |
| A line fails because an easyconfig it depends on is not installed                                                          | The file lists the easyconfigs by name, and the dependency comes later.             | Build from a file of =stack solve= or =stack order=.                 |
